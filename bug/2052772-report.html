Bug 2052772 / D310625 — why the flicker recorder sees the per-window inits

The recorder captures paints until it observes browser-startup-idle-tasks-finished. That notify (②) is the 2nd of two chained ChromeUtils.idleDispatch hops. Both idleDispatch and requestIdleCallback feed the same main-thread idle queue at the same priority — so what matters is enqueue order. Timelines below are from real profiles (t=0 = ① finished task); each has a snapshot of that one idle queue at t=0.

How the events get triggered

Both chains start from the same code path — the first window's _delayedStartup() — then fork and race.

Common origin
window first paint MozAfterPaint→ gBrowserInit._delayedStartup()
├─ forks into two, inside _delayedStartup() ↓
Path A — schedules the per-window inits (line 763 → the init dots below; Origin did this inline with requestIdleCallback, the port routes it through callModulesFromCategory)
_schedulePerWindowIdleTasks()→ callModulesFromCategory("browser-window-idle-tasks", idleDispatch, idleDispatchWindow)→ per-window inits run & paint
Path B — stops the recorder (line 769 → the ② notify / stop marker below)
notifyObservers("browser-delayed-startup-finished")→ BrowserGlue._onFirstWindowLoaded()→ _scheduleStartupIdleTasks()→ browser-startup-idle-tasks-finished task (①)→ 2× ChromeUtils.idleDispatch (②)→ StartupRecorder stops

The race: if Path A's paint-producing inits fire before Path B's stop, their pixels are captured → flicker. The only knob this patch changes is how Path A enqueues onto the idle queue.

recorder capture window (ends at ②) ChromeUtils.idleDispatch ① / ② executes per-window init

The whole difference — one queue, two ways to enqueue

Solution A enqueues the inits as 10 direct idleDispatch callbacks, ahead of ② → ② waits for all of them (and their paints), stop at 187 ms, every init captured. Origin and Solution B enqueue them through the single requestIdleCallback executor, which runs one callback per turn then re-queues itself at the tail → ② gets a slot after just one init (stop 33 / 53 ms) and the paint-producing inits run afterwards. Same queue, same priority — only the enqueue shape differs.
