Address autofill — autocomplete attribute variants

Three structurally identical address forms. All three use the same <label> text and the same name values, so label/id/name inference has identical input in each. Only the autocomplete attributes differ. ids carry a per-form suffix because ids must be unique within one document.

1 — no autocomplete

No field carries an autocomplete attribute, so the browser must infer every field type from its <label>, id and name. Street Address declares autocomplete="unsupport-attribute" — an invalid token, so it should be ignored and fall back to the same inference.

2 — with autocomplete

Every field declares an explicit autocomplete token. Street Address again declares autocomplete="unsupport-attribute" — invalid, so it should be ignored and fall back to label/id/name inference for that field only.

3 — street address as sex

Every field declares an explicit autocomplete token. Street Address declares autocomplete="sex" — unlike unsupport-attribute this is a valid autofill token, just the wrong one for a street address, so the browser should honour it and type the field as sex instead of inferring an address line.
